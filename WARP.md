# WARP.md

This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Project Overview

`serve-my-md` is a markdown-to-static-site generator that consists of two main components:
- **CLI tool** (`cli/`): Node.js CLI that parses markdown files and generates build artifacts
- **Web frontend** (`web/`): React/TanStack Router SPA that renders the parsed markdown

The CLI scans a directory of markdown files, processes them with markdown-it, generates structured JSON output, and builds a static site using the web frontend.

## Architecture

### CLI Component (`cli/`)
- **Entry point**: `src/index.ts` - orchestrates the entire build process
- **Config**: `src/config.json`, `src/smm.config.json` - default configuration files
- **Core logic**: `src/core/index.ts` - handles config reading, ignore rules, HTML generation
- **Utils**: `src/utils/index.ts` - markdown file discovery, parsing, route generation
- **Types**: `src/types/index.ts` - TypeScript interfaces for config and routes

**Build flow**:
1. Interactive prompt for directory selection (if `-i` flag or no directory specified)
2. Parse `.smmignore` file (gitignore-style patterns using minimatch)
3. Read `smm.config.json` for user configuration
4. Recursively scan directory for `.md` files
5. Parse each markdown file with markdown-it (with syntax highlighting via Prism)
6. Generate nested route structure
7. Write `output.json` and `paths.json` to `web/src/`
8. Generate `index.html` with metadata/OG tags
9. Build the React app with Vite
10. Copy dist folder to target directory

### Web Component (`web/`)
- **Framework**: React 19 + TanStack Router (code-based routing)
- **Styling**: Tailwind CSS v4 + shadcn/ui components
- **Build tool**: Vite with React Compiler
- **Key files**:
  - `src/main.tsx` - creates routes dynamically from `output.json`
  - `src/App.tsx` - root layout component
  - `src/components/Rendrer.tsx` - renders parsed markdown HTML
  - `src/components/Sidebar.tsx` - navigation from nested paths
  - `src/output.json` - generated by CLI (routes + content)
  - `src/paths.json` - generated by CLI (nested structure)

## Common Commands

### CLI Development
```bash
cd cli/
yarn dev                          # Compile TypeScript and run CLI
tsc                               # Compile TypeScript only
```

### Web Development
```bash
cd web/
npm install
npm run dev                       # Start dev server on port 3000
npm run build                     # Production build (runs tsc + vite build)
npm run serve                     # Preview production build
npm run test                      # Run Vitest tests
npm run lint                      # Lint with ESLint
npm run format                    # Run Prettier
npm run check                     # Format and fix linting issues
```

### Adding shadcn Components
```bash
cd web/
npx shadcn@latest add button     # Example: add button component
```

## Configuration

### CLI Configuration (`smm.config.json`)
Place in the markdown source directory:
```json
{
  "rootTitle": "Site Title",
  "description": "Site description",
  "baseRoute": "/",
  "defaultTheme": "dark",
  "favicon": "/favicon.ico",
  "logo": "/logo.svg",
  "name": "Site Name",
  "showNameWithLogo": true,
  "publicPath": "./public",
  "markdownItOptions": { "html": true, "breaks": true },
  "og": { /* OpenGraph metadata */ }
}
```

### Ignore Patterns (`.smmignore`)
Gitignore-style patterns to exclude files/directories from processing.

## Important Notes

- The web app uses **code-based routing**, not file-based routing. Routes are generated dynamically in `main.tsx` from CLI output.
- The CLI writes to `web/src/output.json` and `web/src/paths.json` - these files are generated, not source code.
- CLI uses Yarn 4 with PnP (Plug'n'Play), web uses npm.
- Both projects use ESM modules exclusively (`"type": "module"`).
- TypeScript is configured with strict mode and NodeNext module resolution.
- The CLI output directory (`cli/out/`) contains compiled JavaScript - run `tsc` before testing CLI changes.
- React components use the React Compiler via Babel plugin for automatic optimization.
